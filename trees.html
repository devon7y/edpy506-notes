Decision trees and random forests

Instead of fitting one shape to all the data, cut the data into pieces and predict an average within each piece. That one change buys the ability to fit curves a line cannot — and brings a new way to fail.

1Why not a line

Linear and regularized regression both look for the best fitting line, and both work very well when the features and the output have a linear relationship. When they do not, the line has nowhere to go. It cannot capture a non-linear relationship no matter how it is fitted, how many features are added, or how λ is tuned, because the problem is the shape of the model rather than its coefficients.

Decision trees take a different route. They first divide the prediction space into smaller sub-spaces, fit a model within each sub-space, and combine those into a prediction model. For regression the model inside each sub-space is the simplest one there is: the average of the homes that fall in it.

2What a decision tree is

Decision trees, also called classification and regression trees or CART, are one of the best-known supervised learning algorithms, and they work for both kinds of target. A tree predicting a category is a classification tree; a tree predicting a number is a regression tree. The structure is identical.

A decision tree looks like an inverted tree with three parts:

  1. A root node — the starting point of the prediction.
  2. Decision nodes — where the model splits the data into smaller subsets.
  3. Leaf nodes, also called terminal nodes — where the model makes its prediction within a subset.

A prediction is made by walking the splits from the root until you arrive at a leaf, and reading off the value stored there. That process is called recursive partitioning.

Pick a home and watch it fall through. The path it takes is highlighted, and the leaf it lands in is the price the tree predicts for it.

One of the main advantages of decision trees is that the model can be generated visually, with the decisions it takes on display, which helps in understanding its predictive behaviour. Compared with linear regression, CART is also better at making use of categorical features and at handling multicollinearity, meaning high correlations among the features.

3Where a split comes from

Splitting is done in a top-down, greedy fashion. Greedy because a partition performed earlier in the tree will not change based on later partitions: once a split is made it is never revisited, even if a different first cut would have allowed a better second one.

The model begins with the entire dataset and searches every distinct value of every input variable for the predictor and split value that divide the data into two regions, R1 and R2, minimising the overall sum of squared error:

minimize SSE = Σi∈R1 (yi − c1)² + Σi∈R2 (yi − c2)² c1 and c2 are the constants used for the two regions — each is that region's average

Having found the best split, the data are partitioned into the two resulting regions and the process repeats on each of them, continuing until some stopping criterion is reached.

4Growing the tree, and overgrowing it

Repeat that search inside each region and the tree deepens. Every extra level doubles the number of regions available, so the prediction becomes a finer and finer staircase.

Add levels and watch the two error numbers. Training error can only fall, because a deeper tree is a strictly more flexible version of a shallower one. Test error does not have to.

5Pruning

There is a balance to be struck in the depth and complexity of a tree, to get the best predictive performance on unseen data. Deeper nodes tend to overfit to specific attributes of the sample, so a slightly different sample produces highly variable predicted values in the terminal nodes.

The solution is pruning: eliminating some lower-level nodes to stabilise predictions and improve how well the model generalises. It does so at a cost — pruning introduces a certain degree of bias, by design.

Which nodes to cut is decided by a cost complexity parameter, α, which works like the lasso penalty from the previous page: it charges the model for its own size.

minimize SSE + α|T| α is the complexity parameter — at 0, no pruning occurs; |T| is the number of terminal nodes in the tree

Smaller penalties tend to produce more complex models, meaning larger trees. Larger penalties result in much smaller trees. The optimal α is found the same way λ was: train multiple models across a spectrum of α and use cross-validation to identify the best one.

6The other knobs

Besides the cost complexity parameter α, it is common to tune a decision tree with three more:

HyperparameterWhat it setsDefault in Python
Maximum depth The maximum number of internal nodes between the root node and the terminal nodes. no default
Minimum split The minimum number of samples required to split an internal node. 2
Minimum leaf The minimum number of samples required to be at a leaf node. 1

All three do the same job from different directions — they stop the tree before it carves the data down to individual homes. Notice what the defaults imply: a minimum leaf of 1 and no depth limit means that, left alone, a decision tree will grow until every training home has a leaf of its own.

8Random forests

If one tree swings that much, average a lot of them. But trees grown on the same data all look alike, and averaging near-identical models buys nothing. A random forest makes the trees differ on purpose: it decides where to split based on a random selection of features.

How many features each split gets to consider is usually m ≈ √p, where p is the total number of features — so m = 4 for a set of 15 or 16 features.

Rather than splitting on similar features at each node, the trees in a forest are forced apart, because each one splits on different features. That differentiation provides a greater ensemble to aggregate over, and produces a more accurate prediction.

This figure uses all features of the homes rather than age alone, on training homes and held out for testing.

One tree, against a forest of them
Advantages
  • It often works well out of the box, without tuning any parameters.
  • It tends not to overfit.
  • It can handle non-linear numeric and categorical features and output.
Disadvantages
  • A forest is less interpretable than a single decision tree.
  • A forest may require significant memory for storage, because many trees have to be retained.
  • Although random forests can be an improvement on single decision trees, more sophisticated techniques are available.

9Which predictors actually matter

Having built a random forest, we often want to know: which predictors actually matter? The forest has traded the single tree's readable diagram for accuracy, so the question needs answering some other way.

Variable importance ranks features by how much they contribute to the model's predictions. There are two common approaches.

Mean decrease in impurity

How much does each variable reduce impurity, for instance the Gini index, across all the trees on average, whenever it is used to split?

Permutation importance

Shuffle one variable's values, breaking its relationship with the outcome, and see how much prediction accuracy drops.

10Permutation importance, step by step

  1. Train the random forest as usual.
  2. Measure baseline accuracy on test data.
  3. Pick one variable and randomly shuffle its values, destroying its real relationship with the outcome, keeping every other variable untouched.
  4. Re-run predictions with the shuffled data and measure the drop in accuracy.
  5. Repeat for each variable.

A bigger drop means a more important variable. Little or no drop means that variable was not contributing much.

Shuffle the columns one at a time. The table is the test homes — ones the forest has never seen. Scrambling a column leaves every other column where it was, so any change in the error is down to that column alone.
