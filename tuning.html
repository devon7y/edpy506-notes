Model tuning

Most models in the course have settings the data cannot choose for them. Finding good values for those settings without fooling yourself about how well the result will do.

1Parameters and hyperparameters

A parameter is learned from the data during training: a regression coefficient, a split point in a tree. A hyperparameter is set before training begins and controls how the learning itself behaves: the regularisation strength in lasso or ridge, the maximum depth of a decision tree, the number of trees in a random forest.

A hyperparameter cannot be estimated from a single training pass, because training takes it as given. It has to be searched for.

2Why tune a model at all

Default hyperparameter values are rarely the best ones for a particular dataset. Fine-tuning looks for the values that give the best generalisation performance — not the best fit to the training data, which the deepest tree and the smallest λ always win.

The benefits: better accuracy on new, unseen data; less risk of underfitting or overfitting; and a model whose complexity matches the problem's. The risk of skipping it is a model that looks adequate during development and performs poorly once it is deployed.

3Cross-validation: comparing settings fairly

Any search needs an honest way to compare candidate settings, and that is the job of k-fold cross-validation:

  1. Split the training data into k folds of equal size.
  2. Train on k − 1 folds and evaluate on the remaining one.
  3. Repeat until every fold has been the evaluation set once.
  4. Average the performance across all k folds.

That gives a more stable estimate than a single train-test split, and the whole procedure is repeated for every combination of hyperparameters under consideration. With one split, the score depends on which rows happen to land in the test set. With five folds every row is tested exactly once.

4Grid search and random search

Grid search fixes a set of values for each hyperparameter and tries every combination. It is exhaustive and easy to interpret, and it becomes expensive quickly as the number of hyperparameters grows. Random search samples a fixed number of combinations at random from the same space. It often finds settings as good with far fewer trials, especially when some hyperparameters matter more than others. Both are normally combined with cross-validation to score each candidate.

5Tuning three models

Lasso and ridge hinge on λ. A small λ lets the model fit the training data closely and risks overfitting; a large λ shrinks the coefficients harder, which can help generalisation and underfits if pushed too far. In lasso a large enough λ also sets coefficients to exactly zero, which selects features. Define a range of candidate values, evaluate each by cross-validation, and choose the one with the lowest cross-validated error.

Decision trees have several hyperparameters controlling how large they may grow: maximum depth, the minimum samples to split a node, the minimum samples in a leaf. A tree with no depth limit tends to overfit by memorising the training data, and limiting it encourages simpler trees that generalise.

Random forests add their own: the number of trees, the number of features considered at each split, and the depth of each tree. More trees generally improve stability at the cost of training time, with diminishing returns past a certain point. The number of features per split controls how different the trees are from one another, which is an important lever on the bias–variance trade-off.

7The workflow, and why the test set waits

Fine-tuning follows the same five steps whatever the model:

1Define the spacePick the hyperparameters and a range of values for each
2Choose a searchGrid search for a small space, random search for a larger one
3Cross-validateScore every candidate combination on the training data
4Select the bestKeep the combination with the best cross-validated score
5Refit and testRefit on the full training set, then evaluate once on the test set

The test set is used only at the very end, never during the search itself.

8Practical trade-offs

  • Search cost grows quickly. Grid search scales multiplicatively with the number of hyperparameters and the values tried for each.
  • Returns diminish. Past a point, more tuning buys a small gain in performance for a large increase in computation.
  • Go from coarse to fine. A wide, coarse grid or a random search locates the promising region; a second, finer search then narrows the range around those values.
  • Not every hyperparameter needs equal attention. Some, such as the number of trees in a random forest, matter less once a reasonable value is reached; others, such as tree depth, can change performance substantially.
