Feature engineering

What goes into a model decides what can come out of it. Finding the useful columns, putting them in a form a model can use, and dropping the ones that only add noise.

Three parts Extraction and EDA Scaling Categorical features Outliers and missing values Why select features Filter methods Wrapper methods and RFE Domain knowledge first

1Three parts

Feature engineering is three jobs done in sequence: find the information worth using, reshape it into features a model can use, then keep only the features that help.

Feature extractionIdentify the useful information in a dataset
Feature transformationTurn raw features into more robust ones
Feature selectionKeep the most important and informative features

2Feature extraction, and exploratory data analysis

Feature extraction pulls useful information out of a dataset. It aims to compress the data into quantities an algorithm can manage, without distorting the original data or losing significant information. Useful features come from three places: domain knowledge about which features are relevant, a check of data quality — how much is missing and how accurately it was entered — and exploratory data analysis.

EDA summarises and visualises the data before any modelling, showing which features are likely to be useful, redundant, or unreliable. Each check points to a decision about what to keep:

EDA checkWhat it showsFeature selection decision
Distributions — histograms, box plotsSkew, spread, and near-constant valuesDrop near-zero-variance features; flag skewed ones for transformation
Missing valuesThe share and pattern of missing data in each featureDrop features with heavy missingness, or impute them
OutliersExtreme or implausible valuesFix data-entry errors before judging a feature's usefulness
Feature–target relationships — scatter plots, group meansWhich features vary with the outcomeKeep features with a clear relationship to the target
Correlations among features — heat mapRedundant, highly correlated pairsKeep one feature from each correlated pair to limit multicollinearity

3Feature transformation, and scaling

Feature transformation turns raw features into more robust ones, from one representation to another. It covers:

  • Feature creation — merging several features into one, or splitting one into several.
  • Scaling — standardisation, the z-score, to a mean of 0 and a standard deviation of 1; and normalisation, min-max, to a range of 0 to 1.
  • Transformation — a square root, which needs values of zero or more, and a log or reciprocal, which need values above zero.
Standardisation  z = x − meanSD Normalisation  x′ = x − minmax − min

Scaling changes the units of a feature, not the shape of its distribution. Both scalings are computed from the data itself, from its mean and standard deviation or its minimum and maximum. Add a sixth home, far older than the rest, and watch every other home's scaled value move with it.

A square root transformation or a log transformation changes more than the units. Both compress the higher values, so the lower values end up more spread out, and the log compresses high values more aggressively than the square root. The square root needs values of zero or more, and the log needs values above zero. Slide the starting value down through zero and each one runs out of values it can take.

4Categorical features

A model needs numbers, so a category has to be turned into columns. There are two ways:

  • One-hot encoding makes one 0/1 column for every category. It suits tree-based models such as random forests, neural networks where multicollinearity is not an issue, and regularised regression such as ridge, which handles correlated features well.
  • Dummy coding makes one column for every category but one. It suits linear models, logistic regression, and any statistical analysis where perfect multicollinearity — the dummy variable trap — ruins the stability of the coefficients.

5Outliers and missing values

Handling outliers

  • Removal of the outlying cases
  • Replacing them by imputation, or recoding them as missing
  • Capping: set a limit for the feature, and set every value beyond it to the limit
  • Discretisation: turn a continuous feature into a discrete one using a series of intervals

Handling missing values

  • Listwise deletion: keep only cases complete on every feature
  • Pairwise deletion: applicable only to linear models such as linear regression
  • Imputation: replace missing values with estimates. Avoid mean, mode or median imputation; prefer multiple imputation, hot deck imputation, or multiple imputation by chained equations

6Why select features

Feature selection identifies the most important and informative features in a dataset. It is one of the most important steps in a machine learning pipeline, because it has a significant effect on a model's performance and predictive power. Its benefits: better model performance, shorter training time, less risk of overfitting, and more sustainable models.

There are three families of method:

EmbeddedSelection happens inside the model's own fitting: lasso with cross-validation, and feature importance from trees, random forests and boosting
FilterFaster and cheaper, but too simplistic: correlation analysis, and the chi-square test for categorical features
WrapperSelection as a search problem: forward selection, recursive feature elimination, and exhaustive search over every combination

Lasso with cross-validation is on the regression page, and feature importance from a random forest is on the trees page. The other two families follow.

7A filter method: correlation

Correlation analysis keeps the features that are highly correlated with the target and eliminates features that are highly correlated with each other, keeping one of each such pair. Correlation measures a straight-line relationship between numbers, so it applies to numeric features; the chi-square test does the same job for categorical ones.

8Wrapper methods, and recursive feature elimination

A wrapper treats feature selection as a search. Forward selection starts with no features and adds one at a time, whichever improves the model most. Recursive feature elimination, RFE, runs the other way: it considers smaller and smaller sets of features.

  1. Train an estimator, typically a random forest, on the initial set of features, and obtain the importance of each.
  2. Prune the least important features from the set.
  3. Repeat on the pruned set until the desired number of features remains.
The researcher makes three choices RFE cannot make for them: how many features to keep in total, how many to drop in each round, and which algorithm judges importance.

The heart-disease example from the lecture tested RFE by planting four variables among thirteen real clinical features: two of pure random noise, one weakly correlated with the outcome, and one moderately correlated. 9Domain knowledge comes first

RFE selects features from the data alone. It finds whatever patterns exist, but it cannot tell a meaningful one from a coincidental one. Domain knowledge is what lets the results be judged.

Before RFEPredict which features should matter, from how the problem works
Run RFEIt finds the patterns in the data, meaningful and coincidental alike
After RFECheck whether the selected features make sense given what you know

Why house number scores above zero at all

The importance a random forest reports is the total reduction in error from every split on a feature. A column with thousands of distinct values, such as a house number, offers thousands of places to split, and on a finite sample some of them will happen to separate a few expensive homes from a few cheap ones. Each such split is credited to the column. That is a property of the importance measure the forest uses, not evidence that the column matters, and it is exactly the kind of result domain knowledge exists to question.
