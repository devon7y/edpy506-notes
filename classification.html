1What makes it classification

Classification is a predictive modelling problem where a class label is predicted from a set of features. The split from regression is the kind of target: regression predicts a number, classification predicts a category. Everything else about the setup is the same.

Predicting whether a home sells inside thirty days is classification, on the same rows and the same columns that gave a regression problem when the target was the price. Other examples from the same mould: using indicators in a health database to predict whether someone is likely to suffer a heart attack, sorting customer comments into negative, neutral and positive, and predicting whether a bank customer will default on a loan.

There are three shapes the target can take:

Binary

Two possible outcomes. Email spam detection, spam or not. Sold in thirty days, or not.

Multi-class

More than two outcomes, one per case. Sentiment analysis. Fitted either one-vs-rest, one binary model per class against all the others, or one-vs-one, one binary model per pair of classes.

Multi-label

Two or more outcomes, and a case may carry more than one at once. Classifying film genres, where a film can belong to several.

Classification algorithms predict the probability of one class over the others, and usually the probability of one particular category is what matters. An estimate of the chance that an email is spam is more useful than an estimate of the chance it is not.

The algorithms: logistic regression, decision trees, random forest, support vector machines, and k-nearest neighbours. Trees and forests have their own page and work for both kinds of target without modification. The other three are below.

2Why a straight line will not do

The target takes two values. Writing selling inside thirty days as 1 and not selling as 0 makes it numeric, and nothing stops least squares from fitting a line to it.

Y = 0  →  if it did not sell in thirty days
1  →  if it did

The feature is how the asking price compares with the going rate for homes like it. A home priced under the local rate should sell quickly, one priced over it should sit. Move the marker along the price axis and read what each model says the probability is.

A line and a curve, on a target that is only ever 0 or 1
A probability cannot be 1.4, and it cannot be −0.2. The line has no way to know that. It extends forever in both directions because that is what lines do, and the further a home sits from the middle of the data the more confidently nonsensical its answer becomes. What is needed is a curve that bends toward 0 and 1 and never crosses either.

3Logistic regression

Logistic regression models the probability of a binary outcome:

P(Y = 1 | X) = eβ0 + β1X 1 + eβ0 + β1X where e ≈ 2.71828, Euler's number

It is still a regression equation, and it still has an intercept and a slope. The difference is the shape it is wrapped in, which yields values between 0 and 1 whatever β0, β1 and X happen to be.

The same relationship is easier to handle written in terms of the log odds, or logit:

log P(Y) 1 − P(Y) = β0 + β1X a straight line again, on a scale where a straight line is allowed

Drag the two coefficients. The intercept slides the curve sideways and the slope decides how sharply it turns.

The two numbers in a logistic regression

More than two categories

With K categories in the target rather than two, the same function is fitted for each:

P(Y = k | X) = eβ0 + β1X 1 + eβ0 + β1X

K − 1 logistic functions are needed to predict K outcomes, because the last category's probability is whatever is left over. That is multinomial logistic regression.

4k-nearest neighbours

One of the simplest classifiers, and among the most used. KNN is a lazy learner: it does not train a model at all. An observation is assigned to whichever class holds the largest number of its k nearest neighbours. Surrounded by class 1, it is classified as class 1.

Everything happens at prediction time. Given a case with an unknown class, the algorithm finds the k closest cases by some distance measure, those k vote by their own class, and the winner is the prediction.

What counts as close

Distance stands in for similarity: the two closest observations are the two most alike. For observations x and y:

Euclidean  d = √Σi=1n (xi − yi)² Manhattan  d = Σi=1n |xi − yi| Minkowski  d = ( Σi=1n |xi − yi|p )1/p  — p = 1 is Manhattan, p = 2 is Euclidean, and 2 is Python's default
Distance treats every feature as if it were on the same scale. Standardising the features before using a KNN classifier is therefore not optional. Leave it out and whichever column happens to be measured in the largest units decides every vote on its own.

5Choosing k

At k = 1 the prediction on the training set is perfect, because every training case is its own nearest neighbour. As more neighbours are considered the model gets simpler and training accuracy drops. Test accuracy behaves differently: it is low at a single neighbour, improves, and then gets worse again. The best performance is somewhere in the middle.

At the other extreme, with k set to the number of training cases, every prediction is the majority class and the features are ignored entirely.

Accuracy against the number of neighbours
The same curve as on the two previous pages, with a third knob. Complexity was the degree of a polynomial, then the depth of a tree, and here it is 1/k: small k is a complex model that follows every point including the noise, large k is a simple one that averages over distant and irrelevant cases. 6Support vector machines

A family of techniques developed in the 1980s in computer science. Support vector machines work for regression or classification and are mostly applied to classification. The goal is to take groups of observations and construct boundaries that predict which group a future observation belongs to.

Three terms carry the idea:

  • The hyperplane is the decision boundary that classifies the data points. In two dimensions it is a line.
  • The margin is the gap between the hyperplane and the closest points on either side.
  • The support vectors are the points on or nearest to the hyperplane, which influence its position. Move any other observation and the hyperplane does not move at all, unless the move carries it across the boundary of the margin.

When classes are perfectly separable an infinite number of hyperplanes will separate them. The one to take is the one with the largest margin, which is the maximal margin classifier. The hope is that a classifier with a large margin on the training data also has a large margin on the test data, and so classifies well.

Two cases are distinguished by whether such a line exists at all. Linear SVM is when the points can be separated with a straight line. Non-linear SVM is when they cannot, and a non-linear boundary is needed.

7The confusion matrix

Many evaluation metrics exist for testing a classifier, and several are usually used together to decide whether a model performs well enough. Nearly all of them rest on correctly identifying the classes, which is what a confusion matrix tabulates: the number of correct and incorrect predictions, in four cells.

  • True positives (TP) — the actual value is positive and the prediction is positive too.
  • True negatives (TN) — the actual value is negative and the prediction is negative.
  • False positives (FP) — the actual value is negative, but the prediction is positive. A Type I error.
  • False negatives (FN) — the actual value is positive, but the prediction is negative. A Type II error.

A good model has high TP and TN and low FP and FN.

8Accuracy, precision, recall, F1

Accuracy is the proportion of observations predicted correctly, and its appeal is that the explanation is plain:

Accuracy = TP + TNTP + TN + FP + FN correct predictions over all predictions

In the real world classes are often imbalanced, say 95% of observations in one class and 5% in the other. Accuracy then suffers from a paradox: a model can be highly accurate while having no predictive power at all, by predicting the common class every time.

Move the class balance and watch a model that never predicts the positive class at all.

The accuracy paradox

Because of that, precision, recall and F1 are usually calculated alongside it.

Precision = TPTP + FP  — correct positives over all predicted positives Recall = TPTP + FN  — correct positives over all actual positives F1 = 2 × Precision × RecallPrecision + Recall  — the harmonic mean of the two

Precision, also called positive predictive value, is the proportion of everything predicted positive that really is positive. It is the measure to use when the goal is to limit false positives. A model predicting whether a new drug will work in a clinical trial is the example: trials are very expensive, so the model must not produce many false positives.

Recall, also called sensitivity, the hit rate, or the true positive rate, measures how many of the actual positives the model caught. It is the measure to use when every positive must be found and false negatives are what must be avoided. In cancer diagnosis it is important to find all the people who are sick, even at the cost of including some healthy patients.

The two trade against each other. Perfect recall is trivial: predict the positive class for everything, and no positive is ever missed. There are then no false negatives and a great many false positives, so precision collapses. Design for high precision instead and the diagnoses you do make are confident ones, at the cost of failing to identify everyone with the disease, which for those left undiagnosed is potentially fatal. Almost always what is wanted is a balance, and F1 is the single number that takes both into account.

Accuracy, precision, recall and F1 all range from 0 to 1, and higher is better in every case.

9The threshold is a choice

What a classification model returns is a probability. Turning that into a category requires a classification threshold, also called the decision threshold. The default assumption is 0.5, but thresholds are problem-dependent and are a value to tune. Changing it changes the model's measured performance without changing the model at all.

10ROC and AUC

The receiver operating characteristic curve evaluates a model across every threshold at once. It compares true positives against false positives at each one: the horizontal axis is the false positive rate, the vertical axis is the true positive rate, and each point on the curve is one threshold.

Reading it: a classifier that predicts at random traces the diagonal, and a perfect one goes straight up the left edge and along the top. Curves above the diagonal are decent, and the higher up they sit the better. Anything below the diagonal performs worse than guessing.

ROC curves are particularly useful for comparing several classifiers built from different algorithms or different settings.

Every threshold at once

The area under it

AUC measures the entire two-dimensional area underneath the ROC curve, giving an aggregate measure of performance across all possible thresholds. It runs from 0 to 1 and higher is better. A perfect classifier scores 1 and a random one scores 0.5, so anything under 0.5 indicates very poor performance.

AUC treats every classification error equally, ignoring the consequences of one kind over another. On a cancer screen a missed case and a false alarm are not equivalent, and a single number that scores them the same cannot say which model to prefer. That judgement comes from the problem, not from the metric.

Which is where classification arrives at the same place as regression and trees. A model has knobs, the knobs trade one kind of error against another, and no measure chooses for you which kind you can least afford.
