Predicting a number. This page starts with the single straight line that fits a set of homes best, and ends with the reason you would deliberately choose a line that fits them worse.

1What makes it regression

Machine learning splits first on whether the data carry labels. With labels it is supervised; without them, unsupervised. Supervised learning then splits again on the kind of label. A numerical target makes it regression. A categorical target makes it classification.

That second split is the whole of the distinction. Predicting what a home sells for is regression because the answer is a number. Predicting whether it sells within thirty days would be classification, on the same homes, from the same columns.

To benefit from supervised learning at all, the dataset has to contain the target. Without a column holding the answer for each row, there is nothing to learn from, and the problem is an unsupervised one — grouping the homes, rather than pricing them.

Regression algorithms worth naming, all of which do the same job in different ways: linear regression, simple and multiple; regularized regression, meaning ridge and lasso; decision trees and random forests; support vector machines; and k-nearest neighbours. The first four are on this site. This page covers linear and regularized regression, and trees and forests have their own page.

2Fitting a line

Linear regression models the relationship between a numerical target and one or more features, and it is the simplest thing that could work. With one feature it is a line, and the line has two numbers in it:

Ŷ = b0 + b1X or, writing the part the line misses as its own term, Y = b0 + b1X + ε

b0 is the intercept: what the target would be when the feature is zero. b1 is the slope: how much the target moves for each one-unit change in the feature. ε is the residual, the random error — the part of the real value the line does not account for.

One feature makes it simple regression. Two or more make it multiple regression.

3What "best" means: least squares

"Misses by the least" needs pinning down, because there are several ways to add up misses. Ordinary least squares picks the line that minimises the sum of the squared residuals over all n observations:

Sum of Squared Errors = Σi=1n (yi − ŷi)² the quantity the slider above was driving down

Squaring does two things. It makes a miss count the same whether the line is above or below the point, and it makes a large miss count far more than a small one — a residual twice as big contributes four times as much. The fitted line is therefore pulled hard toward the points it is furthest from, which is worth remembering when the data contain an outlier.

There is no searching involved. For one feature, the two numbers have a closed form, and they are what the "solve it for me" button computes:

b1 = Σin (yi − ȳ)(xi − x̄) Σin (xi − x̄)² b0 = ȳ − b1x̄ x̄ and ȳ are the average feature value and the average target

The slope is the extent to which the two variables move together, divided by how much the feature varies on its own. The intercept then simply shifts the line so it passes through the point that is average in both — which is why the fitted line always goes through the middle of the cloud.

4More than one feature

Size is not the only thing that sets a price. With p features the model gains a slope for each one and nothing else changes:

Y = b0 + b1X1 + b2X2 + ⋯ + bpXp + ε

Each slope now answers a narrower question than it did on its own: how much the price moves per unit of this feature, with every other feature in the model held where it is.

A tempting next step is to read the slopes as a ranking of which features matter most. That only works if the features are standardised first. Raw slopes are in the units of their own feature, so the slope on size is dollars per square foot and the slope on bedrooms is dollars per bedroom, and comparing the two numbers compares nothing. Standardise every feature to the same scale and the slopes become β1 … βp, which are comparable: the larger the β, the more important the predictor.

Past two features you cannot draw it any more. One feature is a line on a scatter plot, two is a plane, and beyond that a multiple regression model has no picture. The equation is unchanged and the fitting is unchanged, but the habit of checking a model by looking at it stops being available, which is part of why the numerical scores in the next section matter so much.

5Scoring a fit

R², the coefficient of determination, is the share of the target's variance the model explains — the explained variance over the total variance:

R² = Σin (ŷi − ȳ)² Σin (yi − ȳ)² runs from 0 to 1 — the higher the better

The other three all measure the same thing, the size of a typical miss, and differ in how they punish a big one. All three run from 0 upward, and lower is better.

MAE = 1n Σin |yi − ŷi|  — mean absolute error MSE = 1n Σin (yi − ŷi)²  — mean squared error RMSE = √ 1n Σin (yi − ŷi)²  — root mean squared error

MAE adds up the misses as they are. MSE squares them first, so one badly-priced home counts for more than several slightly-off ones. RMSE is the square root of MSE, which puts the number back into dollars and makes it readable — an RMSE of $70,000 means the model is typically about that far out.

Drag the slider to make the fit worse and watch which measure reacts. At zero the line is the least-squares fit. Moving right tilts it away.

Four scores, one line
The same formulas, applied to data the model never saw, get new names. Compute MSE and RMSE on a validation or test set rather than the training set and they become mean squared prediction error (MSPE) and root mean squared prediction error (RMSPE). Nothing about the arithmetic changes. What changes is what the number is evidence of, and it is the second number that tells you whether the model is any good — as the rest of this page is about.

Advantages

Disadvantages
Linearity assumptionIt can only fit a straight relationship, whether or not the data have one

OverfittingAdd enough features and it fits the training data beautifully and nothing else

Other issues worth knowing before fitting

  • Highly correlated features cause overfitting, so they should be identified and removed before the model is fitted.
  • Predictions are more reliable when the variables are roughly normally distributed. Transforming a skewed variable — a log or a square root — can improve the fit.
  • Predictions are more reliable when the features are on a common scale, which is what normalization and standardization are for.

7Why more features can make it worse

Why is linear regression giving me such good accuracy on the training set but a low accuracy on the test set, despite adding all the available features to the model?

Because prediction error is not one thing. It breaks into three:

Prediction error, decomposed

Bias

The difference between the average prediction and the true value. A model with high bias is wrong in the same direction every time, because it was never flexible enough to be right.

Variance

How much the predictions for a given data point swing across different datasets. A model with high variance gives a different answer every time it is refitted on fresh data.

Noise

Unexplainable randomness in the data, and usually impossible to eliminate. It sets a floor: no model, however good, predicts better than the noise allows.

Bias and variance are the two you can trade against each other. Noise is the one you cannot.

The trade-off is that the two move in opposite directions as a model gets more complex. A simple model has high bias and low variance. A complex one has low bias and high variance. The ideal model minimises both and sits in the sweet spot — not too simple, not too complex — which is where total error is smallest.

The trade-off, drawn
Total error is the sum of the other three. It falls while bias is dropping faster than variance rises, and climbs once that reverses.

Training error alone cannot tell you any of this. It falls all the way to zero as the degree climbs, and it is still falling at exactly the point where the model has become worthless. The only signal that something has gone wrong is the gap between the two numbers, and you only get that by holding data back.

Both failures have a signature worth being able to recognise:

9Regularization, and ridge

Regularization, also called shrinkage, attacks overfitting by reducing model complexity directly. Rather than removing features by hand, it changes what the fitting procedure is trying to minimise, so that complexity has a price. The two best-known methods are ridge, or L2 regularization, and lasso, or L1.

Ordinary least squares minimises the sum of squared errors, and that expression is the loss function. Ridge adds a second term to it — a penalty on the size of the coefficients, scaled by a tuning parameter λ:

Σin (yi − ŷi)² + λ Σj=1p bj² minimise { SSE + λ Σ bj² }

Now a coefficient has to earn its size. Making it larger reduces the first term and increases the second, and it only survives if the error it removes is worth more than the penalty it costs. Small coefficients get shrunk toward zero.

  • When λ = 0 the penalty vanishes and this is exactly OLS.
  • As λ increases, every coefficient shrinks further toward zero.

Drag λ across its range. Each line is one coefficient of a -predictor model, standardised so they are comparable.

Ridge: everything shrinks, nothing leaves
Look at the count of surviving predictors as you drag. It never moves. Ridge shrinks coefficients toward zero and, however large λ gets, does not reach it — every predictor is still in the model, just with less to say. For a model with a large number of features that is a real problem, and it is what lasso exists to fix.

10Lasso, which throws features away

Lasso — least absolute shrinkage and selection operator — changes one thing. Where ridge squares the coefficients in the penalty, lasso takes their absolute values:

Σin (yi − ŷi)² + λ Σj=1p |bj|

That one change makes a difference out of proportion to how it looks. Squaring makes the penalty on an already-small coefficient tiny, so there is almost nothing to gain by pushing it the last of the way to zero. Absolute values keep the pressure constant all the way down, so coefficients are forced to be exactly zero — which drops those features from the model entirely and leaves a simpler one behind.

Lasso therefore performs feature selection as part of training, rather than as a separate step beforehand.

11Choosing λ

λ is not something the data hand you. It is chosen, and the standard way to choose it is cross-validation: split the training data into k slices, usually 5 or 10, then for every candidate λ fit the model on all but one slice and measure its MSE on the slice that was held out. Rotate through the slices, average, and take the λ that minimises the average MSE.

The result is the curve below. Reading it is a small skill worth having:

  • The first dashed line marks the λ with the smallest MSE.
  • The second dashed line marks the largest λ whose MSE is still within one standard error of that minimum. Its model is more constrained and uses fewer features, at a cost in accuracy small enough to be inside the noise — which usually makes it the easier model to interpret and the one to prefer.
Cross-validated MSE against λ
What this whole page has been building toward. Least squares finds the line that fits the data in front of it best, and that is not the same as the line that will predict best. The gap between those two is the bias–variance trade-off, and λ is the dial that sets where on it you sit. Turning λ up deliberately makes the fit to the training data worse, in exchange for a model that holds up on homes it has not seen.

Everything here still assumes the relationship is a straight line, though. When it is not — as with the price and age of a home above — no amount of tuning λ will help, because the problem is the shape of the model rather than the size of its coefficients. That is where decision trees and random forests come in.
